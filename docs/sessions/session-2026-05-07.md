### Bug Fixes

#### Stale Rotation Bug (Kobach bug)
- **Problem:** Player benched on iPad (`isActive = false`). iPhone organizer had stale local session data (bench not yet synced). Organizer recorded a result → rotation engine used stale `players` array → benched player assigned to next match
- **Fix:** `FirebaseTournamentService.recordResult` now re-fetches the latest `players` array from Firestore before running `TournamentRotationEngine.applyResult`. One extra read per result recording, guarantees fresh bench states from all devices

#### No Real-Time Session Sync
- **Problem:** Session loaded once on open. Changes from other devices (bench toggles, results) never appeared without navigating away and back
- **Fix:** Added `observeSession(squadID:tournamentID:sessionID:) -> AsyncStream<TournamentSession>` to `TournamentServicing` protocol. Firebase implementation uses `addSnapshotListener` (nonisolated, inline parsing to avoid actor isolation). Called in `loadDay` — starts immediately, updates `vm.session` on every remote write. `completedMatches` preserved from local state (they live in a subcollection, not the session doc)

## Technical Decisions

| Decision | Rationale |
|---|---|
| `nonisolated` on `observeSession` | Actor-isolated methods can't use `addSnapshotListener` callbacks. Extracted parsing inline to avoid calling actor-isolated serialization helpers |
| `StubTournamentService.observeSession` returns empty stream | Stub is single-device, no real-time needed. Using `nonisolated` avoids the actor isolation data race error |
| Re-fetch players in `recordResult` before rotation | Cheapest correct fix for stale data race. One extra read per match result, no architectural changes needed |
| Preserve `completedMatches` when session stream fires | Session doc never contains `completedMatches` (they're in a subcollection). Without preservation, every remote update would wipe the history tab |
| Delete correction code rather than leave broken | Broken half-features are worse than no feature. Clean deletion with clear deferred note is the right call |

## Issues & Observations

### Multi-Device Testing Surfaced Real Bugs
Testing simultaneously on iPhone (organizer) + iPad (participant) immediately caught two bugs that wouldn't appear in single-device testing:
1. The stale rotation bug only manifests when one device writes bench state and another generates the next match
2. The real-time sync gap is invisible on a single device

### Firestore Subcollection Write Debugging Gap
The correction request feature failed because there was no way to observe whether the Firestore write succeeded or failed — `errorMessage` was set in the VM but no alert was wired to display it. By the time the error display was added, the decision was made to defer. **Lesson: wire error display before debugging Firestore write paths.**

### SourceKit False Positives Throughout
Every new file produced SourceKit errors like "Cannot find type X in scope" for types defined in other files. These are all cross-file resolution failures from SourceKit analyzing in isolation — none were real compiler errors. All resolved with Cmd+B.
