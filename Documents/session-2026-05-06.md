### CLAUDE.md Additions

**Documentation Sync** — After implementing any feature, update all relevant .md files (CHANGELOG.md, checklist.md, README.md, manuals) to reflect the changes. Treat docs as part of the deliverable, not an afterthought.

**Planning Before Implementation** — For multi-step or algorithm-heavy tasks, produce a brief plan with edge cases BEFORE writing code. Wait for user approval on the plan.

**Verification** — Before claiming a file or feature doesn't exist, run Glob/Grep to confirm. Don't assume based on memory of the codebase.

### Features to Try

| Feature | Why it fits |

| **Custom Skills** | Codify recurring doc-sync and spec-review workflows into `/sync-docs` and `/review-spec` slash commands |
| **Hooks** | Auto-run build/lint after edits to catch errors before you do |
| **Task Agents** | Spawn a focused sub-agent for exploration before edits start, avoiding mid-edit scope surprises |

### Usage Patterns

**Plan algorithms before coding them** — Write constraints and edge cases first, dry-run on a small example, wait for approval before implementing.

> *Copyable prompt:* "Before writing any code, list every constraint and edge case, then walk through your proposed algorithm on a 5-player / 1-court example. Wait for my approval before implementing."

**Use checkpoints for large multi-file work** — Ask Claude to commit after each logical step so an interrupted session doesn't lose context.

> *Copyable prompt:* "After each completed sub-task, run `git add -A && git commit -m '<descriptive message>'` so we have recovery points if the session is interrupted."

**Confirm scope before edits** — Have Claude restate the plan in 3–5 bullets before touching files.

> *Copyable prompt:* "Before editing, give me a 3–5 bullet plan: which files you'll touch, what each change does, and what you will NOT change. I'll approve or correct before you start."
